# Agent Instructions

- After creating or changing TypeScript, React, Next.js, or JavaScript code, use the `typescript-react-code-reviewer` skill before reporting the work as complete. Apply any necessary fixes found during that review.
- After finishing code implementation for any ticket or feature, run the `bmad-code-review` skill as a required final review step. Apply any necessary fixes found during that review, then summarize the final outcome.
- Always run the required code-review gates after finishing every task and before committing, pushing, or reporting it as complete. This applies even when the task is small or changes non-application files; report any blocked review or verification instead of treating the task as done.
- Before considering any ticket or feature complete, run a UX/UI review to verify that components are placed where users expect them, the interaction flow follows a clear product logic, and the UI does not mix admin workflows into member-facing experiences unless intentionally designed.
- Before considering any ticket or feature complete, use the QA automation process to define the necessary happy-path, edge-case, negative, authorization, and regression test cases. Implement or update the relevant automated tests and only mark the work complete after the selected verification suite passes.
- Never commit, push, or report a feature as complete when a required verification suite is blocked by missing credentials, unavailable services, or an unverified deployment. Stop and report the blocker first, or resolve the environment and rerun the checks.
- For database-backed features, verify the target environment's migration state and execute a real authenticated smoke path against that environment before committing or pushing. A passing local test suite does not validate a remote deployment.
- Always add validation and expected-format guidance to user-entered fields. Validate both client-side and server-side where applicable, and format specialized fields such as currency, email, phone, dates, and URLs so invalid data cannot silently reach persistence.
- Maintain an estimated task log in `docs/WORK_LOG.md`. When starting a user-requested task, add or update an entry with the prompt/request, branch or issue when available, start time, and planned verification. When finishing, record the finish time, estimated hours, outcome, tests/reviews run, and commit or deployment reference when applicable.
- Always use shadcn/ui components (`@/components/ui/*` e.g., `Select`, `Dialog`, `Table`, `Button`, `Input`, `Badge`, `Card`) for all form fields, select dropdowns, modals, and interactive UI elements across the application. Avoid raw HTML inputs or native `<select>` elements.
- Never use emojis anywhere in the user interface, buttons, titles, cards, or notifications. Always use Lucide icons (`lucide-react`) for professional visual cues.
