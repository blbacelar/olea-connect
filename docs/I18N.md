# Internationalization

Olea Connects supports Canadian English (`en-CA`) and Canadian French (`fr-CA`) through a small locale foundation in `lib/i18n`.

## Locale Resolution

Locale resolution happens in this order:

1. Manual user choice stored in the `olea_locale` cookie.
2. Vercel geolocation headers. Visitors from Quebec (`CA` + `QC`) default to `fr-CA`.
3. The `Accept-Language` request header.
4. `en-CA` as the default fallback.

The middleware sets `Content-Language` and `Vary` headers for the request locale. It does not store inferred geolocation or browser-language choices. Only an explicit selector choice is persisted.

## Manual Selector

`components/i18n/LocaleSelector.tsx` uses the shared shadcn `Select` component and posts locale changes to `/api/locale`. The API stores the manual choice in the server-readable `olea_locale` cookie for one year. The selector is available in the public header and authenticated app header.

## Current Coverage

The public marketing website copy is centralized in `lib/i18n/public-site-copy.ts`, including the landing page, public navigation, pricing, FAQ, final CTA, product preview, and footer. Public referral-program copy lives in `lib/i18n/referral-page-copy.ts`; public sponsorship copy lives in `lib/i18n/sponsorship-page-copy.ts`.

Signup and authentication copy is centralized in `lib/i18n/auth-flow-copy.ts`, including plan selection, account details, payment review, activation success, login, password reset, email verification, password update, invitation acceptance, and activation retry messages.

Authenticated app shell copy is centralized in `lib/i18n/app-shell-copy.ts`, including sidebar navigation, mobile navigation, breadcrumbs, notification controls, and account-menu labels.

Authenticated dashboard modules still contain hardcoded English copy. Translate those areas module by module so each pass can include product review, QA scenarios, and E2E coverage for the affected workflows.

## Adding Copy

For new user-facing text:

1. Add the English and French Canadian strings to the relevant locale dictionary.
2. Keep punctuation, pricing, and legal phrasing precise in both languages.
3. Use `formatCad(value, locale)` for Canadian dollar values.
4. Add or update unit tests when locale selection, formatting, or copy routing changes.
